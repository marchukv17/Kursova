# Лабораторна 1 — Клієнт → Бекенд → База даних

## Мета

Побудувати мінімальний вертикальний зріз вебзастосунку: браузерний клієнт викликає
ендпоїнт бекенду, бекенд читає з бази даних, а клієнт відображає результат.
Відпрацювати базовий Git-процес (репозиторій, форки, pull request'и) і обрати тему
командного проєкту — тут це **скорочувач URL («LinkForge»)**.

## Що зроблено

- Бекенд на Node.js + Express.
- База даних SQLite (через вбудований модуль `node:sqlite`) з таблицею `items`,
  наповненою тестовими рядками.
- Статичний HTML-клієнт, який віддає той самий бекенд.
- Ендпоїнт `GET /items`, що повертає рядки з бази даних.
- Кнопка «Load items» на сторінці, яка викликає `/items` і рендерить список.

Усе запускається через `npm install && npm start` і відкривається на
`http://localhost:3000`.

## Архітектура зрізу

```
Браузер (public/index.html + public/app.js)
        │  fetch GET /items
        ▼
Бекенд Express (src/api/items.routes.js → src/service/item.service.js)
        │  підготовлений запит SELECT id, name FROM items
        ▼
Файл SQLite (data/app.db)  —  таблиця: items(id, name)
```

Це навмисно найкоротший можливий шлях крізь усі три рівні, щоб кожна наступна
лабораторна спиралася на робочу основу.

## База даних

`src/infra/db.js` створює схему при першому старті й наповнює її, якщо вона
порожня.

```sql
CREATE TABLE IF NOT EXISTS items (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL
);
```

Тестові рядки (вставляються, лише якщо таблиця порожня):

1. `Welcome to the URL shortener (lab 1 demo item)`
2. `API contract lives in docs/api/openapi.yaml`
3. `This row is served from SQLite`

Файл бази даних створюється автоматично в `data/app.db` (налаштовується змінною
середовища `DB_PATH`). Для тестів підтримується `:memory:`.

## Ендпоїнт

`GET /items` → `200 OK`

```json
[
  { "id": 1, "name": "Welcome to the URL shortener (lab 1 demo item)" },
  { "id": 2, "name": "API contract lives in docs/api/openapi.yaml" },
  { "id": 3, "name": "This row is served from SQLite" }
]
```

Маршрут навмисно тонкий: він просить у сервісу список і серіалізує його. Сервіс
виконує SQL. Доменний `Item` мапить рядок у форму відповіді.

## Клієнт

`public/index.html` містить картку з кнопкою **Load items** і порожній список.
`public/app.js` прив'язує кнопку до дій:

1. `fetch('/items')` (через стійкий хелпер, запроваджений пізніше в лаб. 5),
2. розбір JSON-масиву,
3. створення одного `<li>` на елемент і додавання до `#items-list`,
4. показ рядка стану («Loaded N item(s) from the database.»).

У разі помилки рядок стану показує повідомлення про помилку.

## Як запустити й перевірити

```bash
npm install
npm start
# у другому терміналі:
curl -s http://localhost:3000/items
```

Очікується: JSON-масив із трьома тестовими елементами. Відкривши
`http://localhost:3000` і натиснувши **Load items**, побачите ті самі три рядки на
сторінці.

Перевірка здоров'я (додана для наступних лабораторних, але корисна вже зараз):

```bash
curl -s http://localhost:3000/health
# {"status":"ok"}
```

## Git-процес

Лабораторна вимагає командного Git-процесу. Маючи цей репозиторій як відправну
точку:

1. Лідер команди створює основний репозиторій і пушить початкову структуру
   (`server.js`, `src/`, `public/`, `docs/`).
2. Кожен учасник **форкає** репозиторій у свій акаунт.
3. Кожен учасник працює у власній гілці у своєму форку, наприклад
   `feat/items-endpoint`, `feat/load-items-ui`.
4. Учасники відкривають **pull request** зі свого форку в репозиторій лідера.
5. Лідер робить рев'ю й зливає; головна гілка завжди лишається робочою.

Рекомендовані назви гілок, використані тут: `feat/db-schema`, `feat/items-api`,
`feat/client-load-items`.

## Чеклист вимог

| Вимога лаб. 1                             | Де виконано                                |
|-------------------------------------------|--------------------------------------------|
| Сервер бекенду (будь-який фреймворк)      | Застосунок Express у `server.js` / `src/app.js` |
| `GET /items` повертає дані з БД           | `src/api/items.routes.js`                  |
| Локальна база SQLite                      | `src/infra/db.js` (`data/app.db`)          |
| Таблиця `items(id, name)` + тестові рядки | `migrate()` + `seed()` у `src/infra/db.js` |
| HTML-сторінка з кнопкою «Load items»      | `public/index.html`                        |
| Клієнт викликає API й рендерить список    | `public/app.js` → `loadItems()`            |
| Обрана тема команди                       | Скорочувач URL («LinkForge»)               |

## Результат

Мінімальна робоча система: браузер завантажує елементи, бекенд їх віддає, а база
даних є джерелом істини. Клієнт ніколи не звертається до бази напряму, а бекенд не
має захардкоджених даних — список справді походить зі SQLite.

## Висновок

Цей зріз доводить повний шлях запиту й дає кожній наступній лабораторній стабільну
основу: лаб. 2 його документує, лаб. 3 моделює домен, лаб. 4 формалізує API та
CRUD, лаб. 5 зміцнює клієнт. Те, що маршрут від початку тримали тонким
(маршрут → сервіс → база даних), одразу окупилося, коли додали ресурс
скорочувача URL.
