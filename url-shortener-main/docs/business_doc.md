# LinkForge — бізнес-документ

## 1. Назва системи й короткий опис

**LinkForge** — це легкий сервіс скорочення URL. Він дозволяє вставити довгу
адресу призначення й отримати коротке, зручне для людини посилання, яке
перенаправляє на оригінальну адресу. Кожне коротке посилання є повноцінним
ресурсом зі своїм ідентифікатором, необов'язковим власним slug, необов'язковим
заголовком і лічильником кліків.

Система навмисно невелика: браузерний клієнт звертається до єдиного HTTP API, який
зберігає посилання в реляційній базі даних. Це засіб для відпрацювання повного
циклу створення вебпродукту — клієнт, бекенд, база даних, документація,
моделювання домену, явний контракт API та стійка обробка помилок.

Продукт орієнтований на окремих людей і невеликі команди, яким потрібні читабельні
посилання для соціальних дописів, документів чи внутрішніх інструментів без
розгортання важкої платформи керування посиланнями. Він віддає перевагу ясності та
надійності над широтою функцій: головна обіцянка — «коротке посилання, яке
продовжує працювати, навіть коли мережа нестабільна».

## 2. Користувачі та ролі

| Роль          | Опис                                                                          | Головні потреби                              |
|---------------|-------------------------------------------------------------------------------|----------------------------------------------|
| **Відвідувач**| Будь-хто, хто відкриває коротке посилання.                                    | Швидкий і надійний редірект на цільовий URL. |
| **Творець**   | Особа, яка створює, редагує та видаляє короткі посилання.                     | Проста форма, передбачувана валідація.       |
| **Оператор**  | Запускає сервіс, стежить за здоров'ям і поведінкою стійкості.                 | `/health`, кореляція запитів, rate limit.    |

Майбутні ролі (поза поточним обсягом): **Адміністратор** (керує зловживаннями,
блоклістами) та **Власник** (посилання за акаунтом, див. контекст Identity).

## 3. Основні сценарії використання

1. **Створити коротке посилання.** Творець вставляє
   `https://example.com/a/very/long/path`, за бажанням задає власний slug `promo`
   і заголовок, надсилає форму й отримує `http://localhost:3000/promo`.
2. **Перейти за коротким посиланням.** Відвідувач відкриває
   `http://localhost:3000/promo`; сервіс знаходить slug, збільшує лічильник кліків
   і повертає редірект `302` на оригінальний URL.
3. **Безпечно повторити.** Мережа обривається під час надсилання форми. Клієнт
   повторює `POST` із тим самим `Idempotency-Key`; створюється лише одне
   посилання, і обидва рази повертається той самий ресурс.
4. **Переглянути й керувати посиланнями.** Творець відкриває застосунок, бачить
   список посилань, оновлює заголовок через `PATCH` і видаляє непотрібне
   посилання.
5. **Пережити перевантаження бекенду.** Бекенд починає повертати `503`/`429`.
   Клієнт робить backoff, дотримується `Retry-After` і після повторних збоїв
   показує банер «сервіс перевантажено» й тимчасово вимикає кнопки.

## 4. Функціональні вимоги

- **FR-1** Система має надавати `GET /health`, що повертає `{ "status": "ok" }`.
- **FR-2** Система має надавати `GET /items`, що повертає демо-рядки з бази даних
  (доказ «клієнт → бекенд → БД» для лаб. 1).
- **FR-3** Система має створювати коротке посилання через `POST /links`, приймаючи
  `originalUrl` (обов'язково), `slug` (необов'язково) і `title` (необов'язково).
- **FR-4** `originalUrl` має валідуватися як абсолютний URL `http`/`https`.
- **FR-5** Власний `slug` має відповідати `^[A-Za-z0-9_-]{3,32}$` і бути унікальним.
  Якщо його не задано, система має згенерувати випадковий 7-символьний slug.
- **FR-6** Система має надавати список посилань (`GET /links`), читання одного
  (`GET /links/{id}`), оновлення (`PUT`/`PATCH /links/{id}`) і видалення
  (`DELETE /links/{id}`).
- **FR-7** Система має перенаправляти `GET /{slug}` на оригінальний URL із кодом
  `302` і збільшувати лічильник кліків.
- **FR-8** `POST /links` має бути ідемпотентним за наявності заголовка
  `Idempotency-Key`: повторний ключ повертає раніше створений ресурс.
- **FR-9** Кожна відповідь має містити заголовок `X-Request-Id`; тіло помилки має
  повторювати його як `requestId`.
- **FR-10** Система має повертати `429` із `Retry-After`, коли клієнт перевищує
  ліміт запитів.
- **FR-11** Усі помилки мають мати єдину форму `{ error, code?, details?, requestId }`.
- **FR-12** Клієнт має повторювати `5xx`/мережеві збої з експоненційним backoff і
  джитером, застосовувати таймаут запиту й входити в режим деградації після
  повторних збоїв.

## 5. Нефункціональні вимоги

- **Швидкодія.** Розв'язання `GET /{slug}` має завершуватися значно швидше за
  100 мс на локальному файлі SQLite; шлях редіректу використовує індексований
  пошук за slug.
- **Надійність.** Читання безпечно повторювати; записи безпечно повторювати через
  ключі ідемпотентності. Збої деградують плавно, а не «вішають» UI.
- **Безпека.** Валідація входу на кожному записі; параметризовані SQL-запити (без
  конкатенації рядків); без секретів у коді; CORS увімкнено лише для локальної
  демонстрації. Автентифікація й виявлення зловживань наразі поза обсягом.
- **Зручність.** UI — одна сторінка: завантажити items, створити посилання,
  побачити список, видалити посилання. Повідомлення про стан однозначні; останній
  request id видно на сторінці.
- **Спостережуваність.** Кореляція запитів через `X-Request-Id`; проба `/health`
  для перевірки живучості; структуровані відповіді про помилки для налагодження.
- **Супровідність.** Суворе розшарування (`api → service → domain`),
  задокументований контракт OpenAPI та юніт-тести рівня service/.
- **Портативність.** Працює з `npm install && npm start` на будь-якій машині з
  Node 22.5+; база даних — один файл.

## 6. Обмеження (чого система точно НЕ робитиме)

- **Без автентифікації та акаунтів.** Немає входу, немає власності на користувача й
  контролю доступу. Будь-хто може створювати чи видаляти посилання.
- **Без терміну дії посилань чи планового видалення.** Посилання живуть, доки їх
  явно не видалять.
- **Без аналітичних дашбордів.** Зберігається лише «сирий» лічильник кліків; без
  графіків, без розбивки за географією/пристроєм, без потоку подій.
- **Без власних доменів чи брендованих коротких доменів.** Усі посилання мають
  спільний базовий URL.
- **Без мультитенантного білінгу / платежів.** Поза обсягом цієї ітерації.
- **Без розподіленої інфраструктури.** Один процес, один файл SQLite; без
  горизонтального масштабування, брокера повідомлень чи кешу в поточному обсязі.
