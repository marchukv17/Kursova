# LinkForge — Ubiquitous Language (глосарій)

Терміни, які поділяють усі в проєкті — розробники, «власник продукту» та будь-хто,
хто читає код. Кожен термін має рівно одне значення в межах свого bounded context.
Там, де слово означало б різні речі в різних контекстах, конфлікт явно позначено й
назви розмежовано.

## Ключові терміни (контекст Links)

### 1. Link (посилання)

Повноцінний ресурс продукту: пара короткого `slug` та `originalUrl` (плюс
необов'язковий заголовок). «Link» — корінь агрегату; це те, що створюють, читають,
оновлюють і видаляють. У UI **не** називайте рядок бази даних «посиланням» — UI
завжди має на увазі доменний об'єкт.

### 2. Slug

Короткий, URL-безпечний ідентифікатор посилання: 3–32 символи з `[A-Za-z0-9_-]`,
глобально унікальний. Slug — це частина після хоста, наприклад у
`http://localhost:3000/promo` slug дорівнює `promo`. Slug ніколи не змінюється,
коли посилання вже існує.

### 3. Short link (коротке посилання / короткий URL)

Публічний, клікабельний URL, побудований з базового URL і slug:
`http://host/<slug>`. Це **похідне значення**, а не те, що зберігається в базі
даних. Коли кажуть «коротке посилання», мають на увазі цей рядок; коли кажуть
«посилання» (link) — доменний об'єкт.

### 4. Original URL (оригінальний URL)

Призначення, на яке розв'язується slug — довгий URL, який вставив користувач. Він
має бути абсолютним URL `http`/`https`. На одне посилання припадає рівно один
оригінальний URL у кожен момент (його можна згодом оновити через `PUT`/`PATCH`).

### 5. Redirect / resolve (редірект / розв'язання)

Акт перетворення slug на його оригінальний URL і повернення HTTP `302` клієнту.
«Resolve» — доменне дієслово; «redirect» — HTTP-ефект. Успішне розв'язання рівно
один раз збільшує лічильник кліків.

### 6. Click (клік)

Одне успішне розв'язання slug (один `302`). У поточному обсязі кліки рахуються, а
не логуються. У майбутньому контексті Analytics клік стає `ClickEvent`; у контексті
Links він лишається звичайним лічильником.

### 7. Click counter (лічильник кліків)

Невід'ємне ціле, що зберігається на посиланні й збільшується один раз за кожне
успішне розв'язання. Він монотонний: ніколи не зменшується й не скидається
оновленнями.

## Наскрізні терміни та розмежування

### 8. Item (елемент)

У **контексті Items** «Item» — це крихітний рядок каталогу лише для читання
(`id`, `name`), що використовується виключно для демонстрації конвеєра
«клієнт → бекенд → база даних» (лаб. 1). Це **не** посилання й не має жодного
зв'язку з посиланнями. Щоб уникнути плутанини, завжди кажіть «item (демо лаб. 1)»,
а не просто «item», коли поруч є контекст Links.

### 9. User vs Owner (користувач vs власник)

- **User** належить **контексту Identity**: акаунт із обліковими даними.
- **Owner** — це те, як **контекст Links** називає ідентичність, що створила
  посилання (`ownerId`), не знаючи подробиць User.

Та сама людина є «User» для Identity і «Owner» для Links. Контекст Links не
повинен імпортувати сутність User; він зберігає лише непрозорий `ownerId`.

### 10. Event vs ClickEvent (подія vs ClickEvent)

Саме слово «Event» неоднозначне, тому його **уникають**. У контексті Analytics клік
— це `ClickEvent` (збережений факт із часовою міткою й метаданими). У контексті
Links ми говоримо лише про «клік» і «лічильник кліків». Це не дає слову «подія»
означати одночасно «HTTP-подію» й «доменну подію».

## Лексика помилок і надійності (лаб. 5)

### 11. Idempotency key (ключ ідемпотентності)

Згенерований клієнтом рядок, що надсилається в заголовку `Idempotency-Key` при
`POST /links`. Два запити з тим самим ключем трактуються як *та сама логічна
операція*: другий повертає перший результат замість створення дубля.

### 12. Request id (ідентифікатор запиту)

Унікальний кореляційний ідентифікатор, що повертається в заголовку `X-Request-Id` і
дублюється як `requestId` у тілі помилки. Він пов'язує дію клієнта з конкретною
відповіддю бекенду для налагодження.

### 13. Degraded mode (режим деградації)

Клієнтський стан, у який система входить після кількох послідовних збоїв: UI
показує банер «перевантажено» й тимчасово вимикає кнопки дій, щоб користувач не
«закидав» запитами бекенд, який ледве тримається.

## Практичні правила

- Віддавайте перевагу доменному іменнику над технічним: кажіть «посилання», а не
  «рядок».
- Тримайте окремо «slug» (ідентифікатор) і «коротке посилання» (повний URL).
- Ніколи не кажіть «подія» без уточнення; вживайте «клік» або «ClickEvent».
- «Item» завжди означає демо-елемент лаб. 1, ніколи — посилання.
